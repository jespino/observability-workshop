Instrumentando tu aplicación con OpenTelemetry

¡Bienvenido a un taller práctico donde instrumentarás desde cero una aplicación real de varios servicios con OpenTelemetry, y enviarás métricas, logs y trazas al stack de VictoriaMetrics! Aproximadamente 25% charla, 75% teclado.

Dos tracks en paralelo: Node.js/Express y Python/Flask. El mismo sistema, el mismo backend y los mismos ejercicios — solo cambia la superficie del SDK.

Prerrequisitos

  • Soltura con APIs HTTP y con JavaScript o Python
  • Docker y Docker Compose instalados y funcionando
  • Git instalado en tu sistema
  • No hace falta saber nada de OpenTelemetry, MetricsQL ni LogsQL
  • Al menos 8GB de RAM libre y unos 5GB de espacio en disco

Descripción General del Taller

Este taller consta de 11 módulos que te llevan desde un servicio que no emite absolutamente nada hasta uno que puedes depurar solo con telemetría. Instrumentarás un sistema de varios servicios, ejecutarás un OpenTelemetry Collector como único punto de entrada y consultarás los resultados en VictoriaMetrics, VictoriaLogs, VictoriaTraces y Grafana:

Cada módulo está escrito una sola vez para los dos tracks. Usa el selector de track de la barra de navegación de cualquier módulo para cambiar los ejemplos de código entre Node.js y Python — tu elección se recuerda mientras avanzas por el taller.

Módulo 0

Preparación y Comprobación del Entorno

Descarga y arranca tú mismo cada pieza del stack — cuatro binarios de telemetría y cuatro contenedores — y después ejecuta el script doctor y guarda las UIs en marcadores.
Módulo 1

La Aplicación que Vas a Instrumentar

Recorre la todo-api que vas a editar durante todo el día — sus endpoints, sus dependencias y el puñado de funciones que importan.
Módulo 2

Qué es Realmente la Observabilidad

Vocabulario común — señales, resource, scope, atributos y contexto — y por qué la correlación es el producto de verdad.
Módulo 3

El Camino Fácil: Auto-instrumentación Sin Código

Haz que fluyan las tres señales sin tocar el código de la aplicación, y descubre hasta dónde llega ese atajo.
Módulo 4

El Collector, y Dónde Acaban los Datos

Lee y modifica la configuración del OpenTelemetry Collector que reparte un único endpoint OTLP entre tres backends.
Módulo 5

Métricas Manuales

Elige el instrumento correcto, emite métricas de negocio, moldéalas con views y enfréntate a la cardinalidad antes de que te muerda.
Módulo 6

Logs Manuales

Emite logs estructurados que arrastren el contexto de traza, y consúltalos con LogsQL.
Módulo 7

Trazas Manuales

Crea spans propios, registra errores como toca y propaga el contexto entre servicios y lenguajes.
Módulo 8

Correlación: Convertir las Tres Señales en Una

Deriva métricas a partir de spans y conecta los saltos entre métricas, logs y trazas en Grafana.
Módulo 9

Proyecto Final: El Reto de Depuración

Diagnostica un fallo desconocido, de los de producción, usando solo la telemetría que has construido.
Módulo 10

Realidades de Producción y Cierre

Coste, sampling, retención, PII y estrategia de despliegue: qué cambia cuando esto sale de tu portátil.

Cómo Empezar

  1. Comienza con el Módulo 0 para dejar tu entorno en verde
  2. Haz los módulos en orden — cada uno se apoya en el anterior
  3. Elige el track en el que quieras escribir, JavaScript o Python. Los dos acaban mirando exactamente los mismos datos.

Consejos para el Éxito

  • Pega las consultas exactas del guion — lo de "explora los datos" viene después
  • Cuando algo pinte mal, lee los logs del Collector antes que nada
  • Usa git para rastrear tus cambios, y los checkpoints de solutions/ para ponerte al día si te descuelgas
  • Compara notas con alguien del otro track después de cada módulo — ahí es donde cala la idea

Recursos

  • Documentación de OpenTelemetry
  • Convenciones Semánticas de OpenTelemetry
  • OpenTelemetry Collector

  • LogsQL de VictoriaLogs
  • VictoriaTraces

Completando el Taller

Al completar todos los módulos, habrás:

  • Instrumentado un servicio real con métricas, logs y trazas, partiendo de cero
  • Ejecutado un OpenTelemetry Collector como punto de entrada único, repartiendo hacia tres backends
  • Elegido los instrumentos correctos y razonado sobre cardinalidad antes de que doliera
  • Emitido logs estructurados que arrastran el contexto de traza, y consultado con LogsQL
  • Escrito spans propios y propagado el contexto entre servicios y lenguajes
  • Correlacionado las tres señales en Grafana y en las UIs de Victoria
  • Depurado un fallo desconocido usando solo telemetría

¡Felicidades! Habrás ganado la confianza para instrumentar tus propios servicios de forma deliberada y no por accidente. Este conocimiento te permite:

  • Añadir a tus servicios telemetría que responda preguntas reales
  • Diseñar dashboards y alertas alrededor de preguntas, no de lo que resultó fácil de emitir
  • Razonar sobre el coste y la cardinalidad de todo lo que recoges
